# M0 产品质量门禁（P0，贯穿所有模块）

## 目标

保证 ReproLab 的演示与真实使用都遵守同一条可信路径：用户知道当前系统是否可用、知道分析将使用什么数据、知道结果是否有完整来源，并能在失败时恢复。

## 研发 DoD

1. 全站通过 `GET /settings/runtime` 使用统一的运行状态和可恢复错误文案；禁止出现原始 `Failed to fetch`、无解释的空白或无限加载。
2. 分析任务提交前确认研究问题和输入数据；真实 Agent 计划仅以 SSE `plan` 渲染，不得用静态文案冒充。
3. 产物卡的可信状态由读取的 Dataset → Run → Artifact 血缘决定；写作回写必须通过校验并至少含一个分析产物锚点。
4. 任何新入口都要覆盖空、加载、错误、成功四态，并具备明确的下一步动作。

## 测试 DoD

1. 后端、数据库、模型密钥、Docker 任一不可用时：页面提示受影响能力和恢复动作，且不泄露密钥或底层错误。
2. 空工作区、已有资料、无可分析数据、分析中、分析失败、血缘不完整、校验失败均有可读状态。
3. 自动化回归至少覆盖：状态接口契约、分析页运行前确认、写作回写拦截、Dataset → Run → Artifact 正常链路。
4. 浏览器回归覆盖桌面和窄屏；键盘可打开命令面板、关闭弹层、提交分析确认，焦点始终可见。
5. CI 在每次推送和拉取请求执行后端单测、前端类型检查与生产构建；需要 PostgreSQL/Docker 的完整验收作为可手动触发工作流，失败时保留服务日志。
