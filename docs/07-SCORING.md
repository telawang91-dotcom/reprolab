# 07 · 评审对齐与演示证据

本文档以正式提交要求和评分标准为准，指导开发取舍、材料组织与现场演示。任何展示都必须来自真实系统状态或明确标识的隔离演示项目，不得把静态示意、测试记录或伪造数据表述为用户研究成果。

## 1. 核心要求

- 技术方向：面向科研前端通用需求，服务科研数据管理、文献检索、智能综述与科研建议生成等场景的智能体系统；
- 必备能力：复杂检索（RAG）、数据分析、长期记忆；
- 数据要求：能够实现多源异构科研数据的结构化管理与查询。

ReproLab 的主叙事不是“又一个科研聊天机器人”，而是：**让科研 Agent 生成的每个数字、图表与论断都能回到数据、代码、环境和证据，并可由评委现场重跑验证。**

## 2. 必备能力覆盖与验证入口

| 核心能力 | ReproLab 实现 | 现场验证入口 | 验证动作 |
| --- | --- | --- | --- |
| 复杂检索（RAG） | 元数据预过滤 + BM25 + pgvector + RRF + reranker；回答生成 `⟦src_*⟧` 证据锚点 | `/knowledge` | 在研究文件夹内切换关键词、语义、智能混合检索，并点开引用原文 |
| 数据分析 | Planner / Executor / Critic 动态生成并执行 Python；运行前确认数据范围 | `/analysis` | 选择 CSV/XLSX，用自然语言提出未预设的分析问题，展示真实 SSE 计划与产物 |
| 长期记忆 | 项目隔离的情节、语义、技能三层记忆；召回前核验范围与来源 | `/memory` | 查看分析后形成的记忆，在新会话中召回已核验偏好或方法 |
| 多源异构管理 | PDF、CSV、XLSX、Markdown、TXT、Python、Notebook 统一入库；项目/文件夹两级隔离 | `/knowledge`、`/projects` | 导入混合文件夹，查看文献片段、数据 schema 与代码资料 |

底线：演示页对能力的说明必须能落到真实页面、REST API 或自动化测试；不能用动画代替实现证据。

## 3. 四项评分策略

### 3.1 科学与应用价值（30%）

评审关心：选题科学意义、问题创新性、实际应用潜力。

ReproLab 的得分证据：

1. 直面科研可复现性与 AI 科研结论可信问题，而非只提高文本生成效率；
2. 将“资料 → 检索 → 分析 → 校验 → 写作 → 复现”连成系统强制的可信路径；
3. 分析机制学科无关，研究生可对真实课题动态生成分析，而非选择写死的学科菜单；
4. 项目与研究文件夹隔离，适合长期管理多个课题，不是一次性对话 Demo。

讲述顺序：先用一个错误数字或数据漂移说明科研风险，再展示系统如何发现、解释与修复，最后再讲架构。

### 3.2 技术深度（30%）

评审关心：智能体复杂度、算法先进性、架构合理性。

| 技术层 | 关键机制 | 可见证据 |
| --- | --- | --- |
| 检索层 | 多路召回、RRF、交叉编码重排、范围预过滤 | 搜索模式、命中片段、引用锚点 |
| Agent 层 | Planner / Executor / Critic；ModelAdapter 模型无关；失败恢复 | SSE 真实计划、执行尝试、自检记录 |
| 可信计算层 | `code_hash = sha256(code + lang + input_hash + env_hash)`；固定随机种子；数值容差比对 | 运行报告、环境快照、Dataset → Run → Artifact |
| 算法增强 | 受控消融漂移归因、引用 NLI、Reflexion 多轮自修复 | 漂移贡献排序、蕴含/中立/矛盾、修复迭代记录 |
| 记忆层 | 情节 / 语义 / 技能三层记忆，按项目隔离并核验后召回 | 记忆列表、来源状态、跨会话复用 |

避免只罗列技术名词。现场至少拆解一次算法输入、输出和失败边界，例如解释漂移贡献度如何由逐项回放得到，以及 NLI 为什么比字符串匹配更能识别虚假支持。

### 3.3 技术落地性（20%）

评审关心：可实施性、工程完整度、成果可复现性。

验证证据：

1. FastAPI REST 能脱离前端完成 Agent 调用，入口为 `POST /agent/invoke`；
2. PostgreSQL 16 + pgvector 统一承载元数据、向量与溯源边；对象按内容哈希存储；
3. 沙箱记录代码、输入哈希、环境快照、随机种子、stdout 与产物；
4. `/settings` 显示数据库、模型和沙箱的真实状态及恢复动作；
5. 后端单测、前端类型检查与生产构建进入 CI；完整 PostgreSQL/Docker 验收可手动触发；
6. 隔离演示项目不污染真实研究空间，自动化测试只允许连接名字明确含 `test` 的数据库。

不要把“能启动页面”当作落地证据；应展示真实 API、真实运行记录和可重跑报告。

### 3.4 演示效果（20%）

固定三分钟主线：

1. **0:00–0:25，问题与定位**：一句话说明“AI 能生成答案，但科研需要能追责、能重跑的答案”；
2. **0:25–0:50，资料与检索**：进入隔离演示项目，展示研究文件夹范围与混合检索证据；
3. **0:50–1:35，真实分析**：提出自然语言问题，确认输入数据，展示 Planner / Executor / Critic 与真实产物；
4. **1:35–2:15，招牌动作**：打开 Dataset → Run → Artifact，替换数据重跑，结果标红并定位漂移来源；
5. **2:15–2:45，评委找茬**：在写作页加入错误数字或弱引用，运行 NLI 校验与反思式修复；
6. **2:45–3:00，长期价值**：展示项目记忆与复现报告，收束到“越用越懂你，但每次复用仍可核验”。

演示纪律：

- 先检查 `/settings`，数据库、模型或沙箱异常时立即说明受影响能力；
- 真实运行与“演示说明”必须有清晰视觉区分；
- 主流程只保留一个下一步动作，技术细节由评委追问时展开；
- 准备一条纯 REST 备用路径和一份已生成的真实运行报告，防止现场网络或模型服务波动；
- 不依赖临时伪造的文献、数字或运行记录。

## 4. 评委可亲手验证清单

1. 导入一个同时包含论文、数据与代码的文件夹，确认范围隔离和结构化解析；
2. 用智能混合检索提问，点击 `⟦src_*⟧` 回到原文片段；
3. 提出未预设的数据分析问题，检查生成代码和运行输入；
4. 点击任意产物查看 Dataset → Run → Artifact 及环境哈希；
5. 修改输入后重跑，观察容差判定、漂移标红和贡献排序；
6. 输入无来源数字或弱支持引用，观察校验拦截与自修复记录；
7. 打开新会话，验证长期记忆是否按项目召回；
8. 直接调用 `POST /agent/invoke`，证明核心能力不依赖前端；
9. 切换 ModelAdapter 配置，确认可信链与校验规则不随模型供应商改变。

## 5. 当前优化优先级

1. **P0：演示稳定性**——隔离演示必须一步进入可分析的研究文件夹；运行状态、空态、错误态和恢复动作完整；
2. **P0：证据可见性**——RAG、记忆、漂移归因、NLI、自修复不能只存在于代码和文档，必须从主线进入；
3. **P1：真实演示素材**——使用明确授权的开放文献与公开数据，预先完成一次真实运行并保留报告；
4. **P1：量化材料**——记录检索命中、复现一致率、校验发现率、修复轮次与端到端时延，避免只有定性描述；
5. **P2：生产增强**——身份认证、细粒度权限、备份恢复、监控与并发压测，不阻塞比赛主闭环。
