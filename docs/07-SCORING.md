# 07・评审对齐（Scoring Alignment）

本文件用于大赛四维评审标准对齐，拆分项目得分抓手、开发资源投入优先级，避免无效开发。

## 1. 评审权重与核心战略结论

表格







|    评审维度    | 权重 |            评审核心侧重            |
| :------------: | :--: | :--------------------------------: |
| 科学与应用价值 | 30%  |      选题创新性、真实科研痛点      |
|    技术深度    | 30%  |   底层算法先进性、差异化技术设计   |
|   技术落地性   | 20%  |  工程可实施、一键部署、接口化调用  |
|    演示效果    | 20%  | 交互直观、完整业务闭环、可现场验证 |

### 战略结论

总分 60% 权重集中于「科学创新价值 + 技术算法深度」，为本项目核心打磨战场；落地、演示模块现有方案已成熟，仅做守成优化，不再额外投入大量开发资源。

### 风险提示

仅靠溯源哈希、RRF 融合检索、第三方 reranker 无法支撑 30% 技术深度得分；新增三类自研算法模块补足技术先进性短板（P1 优先级，P0 基础闭环完成后开发）。

## 2. 科学与应用价值（30%・选题创新）

### 科学高度

直击全球公认「科研可复现性危机」、科研诚信痛点；区别于通用科研对话大模型，本项目从底层架构解决实验结果无法复现、论文数值与代码不匹配行业问题，科学叙事完整厚重。

### 应用刚需

解决研究生三大核心痛点：实验记录混乱无法回溯、分析流程难以复现、大模型输出结论可信度低；跨学科通用（经管实证、生物统计、环境、心理实验等）。

### 三层系统级创新（核心得分点）

1. 全链路可信闭环：检索→分析代码执行→对抗校验→一键复现→报告回写，将可复现规范由人工约束转为系统强制流程；
2. 架构级模型无关可信体系：可信保障依托账本、质检架构，不依赖大模型能力；低成本弱幻觉模型仍可产出可溯源可信结论，赛道独一定位；
3. 算法化自动核查：将人工审稿纠错升级为自动化算法校验（差异归因、语义蕴含判断、自修复循环）。

### 现场演示抓手

完整跑通「文献检索→数据分析→生成带锚点结论→修改数据集复现自动标红漂移」全流程。

## 3. 技术深度（30%・算法先进性）

### 3.1 已有基础技术深度（内置方案）

带全环境快照的 code_hash 信任锚溯源账本、容差可控分类型复现比对 + 全局随机种子、向量 + BM25+RRF + 交叉编码器混合检索、多角色模型路由架构、对抗式三查校验流水线。

### 3.2 新增自研算法增强模块（拉高评审得分，P1 优先级，ROI 从高到低）

#### ① 漂移归因 Drift Attribution（tasks/M5b-drift-attribution.md）

功能：复现出现数值漂移时，算法自动定位导致结果变化的数据行 / 列 / 超参数，输出变量贡献度排序；底层采用受控消融、敏感性分析、留一法 / Shapley 归因思路。

拉分优势：纯自研数值算法，演示冲击力强，现场可展示「精准定位哪一列数据导致系数偏移」。

#### ② 引用语义蕴含检测 NLI（tasks/M7b-citation-nli.md）

功能：三查模块「文献是否支撑论断」标准化为 NLI 文本蕴含任务，输出 entailment/neutral/contradiction 标签、置信度、证据原文片段；可专用 NLI 模型或 LLM-as-judge 实现。

拉分优势：标准 NLP 学术任务，将简单字符串匹配升级为语义算法，实现自动识别张冠李戴虚假引用。

#### ③ Reflexion 反思式自修复循环（tasks/M7c-reflexion-repair.md）

功能：质检识别缺陷后，自动反馈写作 / 代码 Agent 迭代修正，多轮校验闭环直至全部通过；理论支撑 Reflexion、Self-Refine 经典 Agent 论文。

拉分优势：前沿多智能体自校正算法，具备学术理论背书，拔高项目技术上限。

### 现场验证抓手

1. 漂移归因展示变量贡献排序；
2. 切换不同 LLM，溯源校验链路完全不受影响，证明模型无关架构；
3. 拆解三查、归因底层算法逻辑。

## 4. 技术落地性（20%・守成无需额外投入）

工程基础：全栈成熟 Python 技术栈（FastAPI 后端 + PostgreSQL/pgvector 向量库）、docker-compose 一键部署、原始数据本地存储（仅 LLM API 网络请求）、Agent 核心逻辑无前端依赖，支持 HTTP 接口远程调用；

现场验证：脱离前端页面，直接调用`POST /agent/invoke`接口完成完整溯源分析任务。

## 5. 演示效果（20%・守成优化）

固定三大高分演示动作：

1. 修改数据集一键重跑，自动标红漂移数值 + 漂移归因根因；

2. 手动插入虚假数字 / 虚假文献，质检实时标红并输出 NLI 语义冲突理由；

3. 存在缺陷草稿触发自修复循环，多轮迭代后校验全部通过；

   

   配套成熟 Linear 级专业 UI、评委手动找茬交互环节，现有方案完整，无需新增功能。

## 6. 评委可亲手验证完整抓手清单

1. 点击任意正文数字 / 引用上标，一键回溯原始代码、数据集或原文文献；
2. 替换数据集复现，自动标红漂移数值，归因算法输出根因变量；
3. 手动输入无来源数字、虚假引用，系统实时识别并展示失败理由；
4. 存在错误的报告草稿自动迭代修复，直至三查全部通过；
5. 纯 HTTP 接口调用后端核心能力，不依赖前端页面；
6. 切换不同大模型，全链路溯源、校验逻辑正常运行。

## 7. 单人开发 3–5 周投入优先级

1. P0 核心闭环优先完成：M1 知识库入库 → M2 混合检索 → M4 沙箱执行捕获 → M5 溯源复现引擎 → M3 分析对话 Agent；
2. 高 ROI P1 模块：漂移归因 Drift Attribution；
3. 次优先级 P1：NLI 引用蕴含检测；
4. 剩余时间补充：Reflexion 反思自修复循环；
5. 落地工程、前端演示维持现有方案，不新增功能开发。
