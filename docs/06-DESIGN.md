# 06・UI / UX 设计规范

开发所有前端页面、组件前必读；目标：专业科研工具产品质感，规避业余粗糙交互。

### 技术栈

shadcn/ui + TailwindCSS + lucide 图标 + reactflow（溯源图谱）+ react-markdown/katex（公式富文本）+ framer-motion（交互动效）

## 0. 视觉北极星（统一对标产品）

- 产品外壳、留白、排版与单一交互色：Apple 风格
- 科研工作流的信息克制与单任务聚焦：腾讯 ima / AutoResearch 式工作台
- 引用 / 数字锚点交互、弹窗来源卡片：Perplexity

### 对标细节拆解

1. Apple 借鉴点：系统字体、大标题紧字距、正文 17px、宽松留白、胶囊式主操作，以及通过浅灰 / 白 / 深色内容区分层次；

2. ima / AutoResearch 借鉴点：以“下一步研究动作”而不是功能目录组织首页；次要设置收进菜单，避免并列按钮争抢注意力；

3. Perplexity 借鉴点：正文数字 / 引用可点击上标角标，hover / 点击弹出来源详情卡片，页面顶部来源汇总条；

   

   整体气质：安静、有识别度、专业；让研究材料和结论成为视觉主角。品牌极光渐变仅可用于首页 / 引导的主视觉、主操作和可点击任务卡图标，不得用在正文、数据表格或错误状态中。

## 1. 设计令牌（Design Tokens）

### 颜色体系（浅色默认，深色镜像）

#### 主色

主强调：科研靛蓝 `#5B5CE2`；hover 态 `#4748C9`；主视觉渐变 `#171B4D → #4F46A5 → #0891B2`；交互卡图标可使用天空蓝 / 靛蓝 / 紫红三组同亮度渐变。

#### 中性色（浅色）

背景羊皮纸 `#F5F5F7` / 卡片 `#FFFFFF` / 边框 `#E0E0E0` / 分割线 `#F0F0F0` / 正文 `#1D1D1F` / 次要文字 `#7A7A7A` / 占位 `#A1A1A6`

#### 语义状态色（全站统一）

可复现 / 校验通过：绿 `#16A34A`；漂移 / 错误告警：红 `#DC2626`；运行中 / 待校验：橙 `#F59E0B`；普通信息：蓝 `#2563EB`

#### 深色模式基底

背景 `#000000` / 卡片 `#1D1D1F` / 边框 `rgba(255,255,255,.12)` / 正文 `#F5F5F7`

### 字体规范

1. 界面正文：`SF Pro Text` / `-apple-system` / 系统无衬线；中文 fallback `PingFang SC`、`Microsoft YaHei`；
2. 代码 / 哈希 / 数值等等宽内容：JetBrains Mono；
3. 字号阶梯：12 / 14 / 15 / 17 (正文基准) / 21 / 28 / 40 / 56；正文行高 1.47；标题字重 600、紧字距；常规文本只用 400，避免 500。

### 间距、圆角、层级（8px 栅格基准）

- 间距刻度：4 / 8 / 12 / 17 / 24 / 32 / 48 / 80
- 圆角：工具卡 18px；紧凑控件 8px；主操作与搜索输入 9999px 胶囊；
- 阴影：正文卡片使用低对比 `0 12px 32px rgba(15,23,42,.06)`；可点击任务卡 hover 时可增强至 `0 18px 42px rgba(79,70,229,.14)`，其余场景禁止厚重阴影。

### 动效令牌

常规过渡 150ms ease-out；页面入场 200ms；校验结果（绿勾 / 红叉）强调动效 300–400ms 弹性曲线。

## 2. 全局 UX 强制原则（全页面通用）

1. 溯源随手可达：所有结果卡片、结论区域右上角常驻「查看来源」按钮；正文数字、文献引用永久为可点击角标；
2. 流式实时反馈：检索、代码分析、质检全流程流式分步渲染（规划→思考→代码→产物），禁止空白加载等待；
3. 三态完整：所有数据模块必须实现空状态（操作引导）、骨架加载态（不使用旋转 spinner）、错误态（可读报错 + 重试 / 编辑按钮）；
4. 强视觉状态反馈：复现、漂移、校验失败使用专属动效收尾；
5. 键盘优先：Cmd/Ctrl+K 全局命令面板，核心操作绑定快捷键；
6. 信息克制：单页面仅保留 1 个核心任务，次要功能折叠抽屉，减少冗余按钮；
7. 语义色统一：绿 = 可信可复现，红 = 漂移 / 错误，橙 = 执行中，全站无歧义；
8. 非阻塞后台任务：入库、长时分析后台异步执行，前端持续可交互；

### 2.1 可信状态与可恢复错误（P0）

1. 不得向用户暴露浏览器或底层网络错误（如 `Failed to fetch`）；统一转为“受影响能力 + 原因 + 下一步操作”的可恢复状态卡。
2. 工作区外壳在后端、数据库、模型或沙箱未就绪时，显示一条可点击的细窄状态条；它不遮挡当前内容，点击进入设置的运行状态区。
3. 分析开始前须出现“运行前确认”层：列出研究问题、选中的数据集及行/列概况，并明确将保存数据版本、代码、随机种子和环境快照。此层不是伪造的 Agent 分析计划；真实计划仍由 SSE `plan` 事件渲染。
4. 产物卡不得静态声称“可信记录完整”。必须先读取血缘，确认 Dataset → Run → Artifact 链路存在后显示绿色；读取中为中性态，链路不全为橙色待核对态。
5. 写作页面的默认身份为“草稿”；只有三查通过且至少包含一个 `⟦art_*⟧` 锚点后，才可显示“可信结论”并允许回写。

布局细节：

2. 顶部导航栏：项目切换、全局搜索入口、深浅色切换、用户头像；

4. 顶栏项目切换器必须展示真实当前项目；菜单支持切换、新建与查看归档项目。切换时显示短暂加载态，禁止残留前一项目的内容。
5. 空工作区提供“上传我的资料”和“使用示例数据体验”两个入口；后者必须切换至隔离演示项目，并明确不会写入用户当前项目。

### 4.1 研究交付、时间线与审阅（P1）

1. 工作台非空时提供一条紧凑“研究时间线”，只展示资料、运行、漂移、校验和结论等可回溯事件；每项可回到原始页面。
2. 复现报告以可打印 HTML 呈现，优先展示研究问题、输入数据版本、代码哈希、环境、产物、复现结论；技术原文折叠。
3. 导师审阅页必须为只读、摘要优先：项目健康度、已验证/待修正结论、近期可信产物和明确下一步。不得把密钥、完整隐私数据或底层错误暴露给审阅者。
4. 引用阅读器打开后先显示命中证据段落、章节和位置，再展示文档元数据；“直接支持/待人工判断”使用文字与图标，不只靠颜色。

## 4. 逐页面线框、组件、状态定义

### P1 工作台（首页，M10/M5 展示）

plaintext









```
┌ 今天想推进哪一步？ ───────────────────────────────────────┐
│ [查资料与问文献] [分析一份数据] [整理可信结论]             │
├ 当前研究进度 ───────────────────┬ 建议下一步 ─────────────┤
│ 资料入库 → 限定范围 → 运行分析 → 写入结论 │ 按当前状态给单一主动作 │
├ 基于证据的下一步 ─────────────────────────────────────────┤
│ 建议只引用已入库资料 / 真实产物，证据角标可回溯             │
└───────────────────────────────────────────────────────────┘
```

页面要点：

- 首页按用户任务组织，不要求用户先理解系统模块；
- 可信闭环“资料 → 范围 → 分析 → 结论”作为核心进度模型；
- 非空工作区必须提供“最近资料 / 最近空间”继续入口，降低回访用户的找回成本；
- 每条智能科研建议附带可点击证据角标，回溯原始文献 / 数值产物；
- 空状态只给一个当前最合适的下一步动作，避免并列入口争抢注意力。
- 首次进入只提供可选产品演示入口；演示不写入真实知识库。空工作区保持干净，只给“添加资料”这一主动作。

交互规则：

1. 搜索三模式切换：关键词 / BM25、语义 / 向量、混合融合检索；

3. 检索结果：命中文本高亮，每条卡片附带「定位原文」按钮；点击文件右侧滑出预览抽屉 Sheet；
4. 加载态：文件卡片骨架占位；入库中卡片显示橙色进度角标。
5. M1b：桌面端使用“左侧知识空间导航 + 右侧当前空间工作区”，移动端降级为顶部空间选择器；当前空间同时约束文件列表、检索和问答。上传支持多选、文件夹和 ZIP，后台任务显示进度条与逐文件失败原因；“全部资料”保持旧的项目级行为。

```
┌ 会话/数据集(w260) ┬ 对话流(flex) ────────────┬ 产物预览(w360) ┐
│ ▸ 数据集          │ 用户: 画箱线图并检验       │ [图/表/数字]    │
```

流式渲染顺序（SSE 推送）：规划步骤条 → 可折叠思考文本 → 高亮代码块（支持编辑重跑）→ 执行状态（橙色脉冲运行中 / 绿色通过 / 红色失败）→ 产物卡片 → Markdown+katex 带锚点结论；

功能细节：

1. 产物卡片右上角固定「查看来源、重跑、回写报告」操作；
2. 代码执行中：代码块顶部橙色脉冲进度条；
3. 空状态：页面中央引导文案 + 示例 Prompt 快捷芯片；
4. 失败态：红色 stdout 报错摘要，附带自动修复重试、手动编辑代码按钮。

## 5. 核心演示动效（framer-motion）

1. 复现结果：进度条完成；匹配一致 = 绿色对勾弹性缩放 (0.8→1.1→1)；漂移 = 红色叉号左右抖动 ±4px，卡片红边框，差异面板从右侧滑入；
2. 溯源链路高亮：点击结论节点，上游节点 / 边间隔 80ms 依次主色描边点亮；
3. 校验错误标红：不合格锚点下划线 200ms 平滑过渡为红色，hover 悬浮提示失败理由；
4. 产物卡片入场：透明度 0→1，纵向位移 8px→0，200ms 过渡。

## 6. 全站统一锚点渲染规范（Perplexity 风格）

1. `⟦art_xxxx⟧`：蓝色可点击上标；弹窗展示产物完整血缘链；
2. `⟦src_xxxx⟧`：灰色可点击上标；弹窗文献卡片，支持跳转原文段落；
3. 校验失败锚点：红色角标 + 悬浮提示；
4. 无锚点裸数字：预览页红色波浪下划线标记；
5. 统一封装组件：`components/anchor/AnchorChip.tsx`，对话、写作、问答页面复用。

## 8. 响应式与无障碍规范

1. 主适配桌面屏幕≥1280px；宽度 < 1024px 时三栏布局折叠为 Tab 切换；
2. 色彩不可作为唯一状态标识，红绿状态搭配✓/✗图标；文本对比度满足 WCAG AA 标准；
3. 所有可交互元素拥有主色 focus 焦点环；弹窗、抽屉支持 ESC 快捷键关闭。

## 9. 首次使用与工作台首屏（P0）

1. 首页首屏应先回答“我现在在哪里、项目里有什么、下一步做什么”，采用研究驾驶舱式摘要；不得以模块目录或空白表格作为首次视觉焦点。
2. 新用户在首页获得可关闭、可继续的三步引导：添加资料 → 建立研究范围 → 运行分析。引导进度仅基于真实资料与知识空间状态，不伪造“已完成”。
3. 完整指南不是功能说明书；每个步骤必须有一个直接可执行的页面入口，并在页面内说明用户将得到的结果和可信边界。
4. 首页、指南与侧栏使用一致的视觉骨架：深色研究主视觉只用于定位与强调，正文工作区保持高对比、低噪声的浅色表面；渐变只能用于背景层，不得干扰数据、代码和状态阅读。
5. 新手引导可被关闭，不得在用户已主动关闭后反复遮挡工作；侧栏始终提供“新手引导”入口，便于随时回到流程。
6. 所有“能力 / 模板 / 下一步”卡片必须可点击并指向真实功能页；纯信息卡必须使用非按钮样式，避免造成可点击错觉。
7. 动效只服务反馈：可点击卡片在 hover 时可轻微上移，图标和主视觉可做低频漂移；应尊重 `prefers-reduced-motion`，不得自动移动正文内容。

## 10. 默认工作台的信息克制（P0）

1. 默认首页只表达用户可做的事：添加资料、开始分析、继续项目；不得在首屏解释溯源、哈希、环境、复现或校验等实现机制。
2. “可信、可复现、数据—代码—环境”等差异化能力放在新手引导、帮助说明、运行结果与校验失败场景中按需出现；用户不应先学习机制才能开始工作。
3. 导航优先使用任务词：资料、分析、写作、记录、时间线、审阅；避免“可信记录”“结论写作”“导师审阅”等带解释负担的命名。
4. 工作区优先级固定为：一个主操作、少量最近内容、一个可选的下一步建议。完成项目后不展示流程图、指标墙或静态价值陈述。
5. 品牌渐变收敛为低饱和深靛蓝至石板蓝；禁止同时使用高饱和青、紫红、粉色作为主界面色。交互感来自 hover 抬升、边框高亮、按钮按压与明确跳转，而不是堆叠更多颜色。

## 11. 产品化信息架构与连续工作流（P0）

1. 一级导航固定为“工作台、资料、分析、成果、项目”，不得把时间线、审阅、记忆、指南、设置和个人资料并列为一级工作入口。
2. 用户主路径固定表达为“添加资料 → 运行分析 → 检查成果 → 形成报告”，核心页面顶部复用同一流程条，并根据真实项目状态标记进度。
3. “成果”统一收纳成功运行、分析产物、可信状态与结论入口；溯源、复现、时间线和导师审阅作为成果或项目的二级动作。
4. 所有涉及写入的移动端页面必须可见当前项目名称；归档项目明确显示只读状态。
5. 页面标题统一使用“眉题 + 28–32px 主标题 + 单行任务说明”，正文内容控制在 1200px 内；数据密集页允许全宽，但必须保持同一页边距。
6. 默认状态只展示用户语言“来源完整、待检查、发生变化”，Dataset、Run、Artifact、hash 等技术词汇进入展开详情。
